## 1. Propósito de esta entrega

Diseñar el flujo de experiencia de usuario del módulo Pacientes **por rol**, incluyendo
estados (carga, vacío, error, éxito), mensajes de ayuda y reglas de interacción — sobre el
contrato ya implementado y probado en semanas anteriores (`docs/module-03/contrato-api.md`),
no como un diseño aspiracional aparte.

Hasta esta semana el módulo era solo una API backend (ver `docs/modulos/mod03/semana-07-componentes-refactor/README.md`,
sección "Propuesta frontend" en `COMPONENTES.md`). Esta entrega diseña por primera vez la
capa de interacción humana sobre esa API.

## 2. Estructura de esta entrega

```text
semana-08-ux-flujo/
├── README.md            # Esta ficha
├── FLUJO_UX.md           # User flow por rol, estados y reglas de interacción
└── WIREFRAMES.md         # Wireframes de baja fidelidad de las 3 pantallas
```

## 3. Trazabilidad

Cada pantalla y cada estado de `FLUJO_UX.md` corresponde a un endpoint y a una respuesta real
documentados en [`docs/module-03/contrato-api.md`](../../module-03/contrato-api.md) — no se
inventó ningún campo, permiso ni mensaje de error nuevo.
